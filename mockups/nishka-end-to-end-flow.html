The whole conversation — welcome buttons, carousel, balance card, live-agent handoff — is rendered by the Cimulate widget inside the WebView. Only the login, home, and PDP are native screens. The product tap (step 5→6) is the URL-interception bridge from §7; the authenticated balance (step 8) rides on the verified JWT identity from §10; the live-agent escalation (steps 9→10) is MVP and depends on MIAW push + conversation resume from §11.

Where each step is handled

  1. Login — native app auth; app now holds the session and can mint a signed JWT for MIAW user verification. MVP · §10
  2. Ask Nishka — native entry control opens the WebView; widget connects to SCRT2 with the verified identity + routing attributes. MVP · §5–§6, §10
  3. Welcome buttons — agent’s opening menu (quick-reply buttons), rendered by the widget. MVP · agent config
  4. Guided intake — agent asks recipient → occasion → product type via quick-reply chips; answers scope the search. MVP · agent config
  5. Discover products — agent returns a product carousel + chips scoped to the intake; widget renders it. MVP · §1
  6. Native PDP — product tap intercepted, web nav cancelled, app’s PDP pushed. MVP · §7
  7. Back to chat — WebView retained, conversation + scroll preserved. MVP · §7, §8
  8. Digigold balance — agent action calls the Tanishq API keyed on the verified JWT identity (never a client-set field). MVP · §10
  9. Talk to an agent — agent escalates; Omni-Channel routes the conversation to a queue of human agents. MVP · §11
  10. Live agent — a human picks up the same thread. Replies can arrive minutes/hours later, so this needs MIAW push + conversation resume. MVP · §11

The digigold balance is fetched by the agent action on the shopper's verified identity — the signed JWT the app hands to MIAW user verification (§10), never a client-supplied field. Registering that verification with the widget is tracked as item 1 in the guide's §14.
